## 1. Lifecycle of a brand-new post

### 1a. t = 0s — Thunder (in-network store)
- Ingest from the tweet-events Kafka stream (`thunder/kafka/tweet_events_listener.rs:209-244`). Nullcast posts are skipped (:220-224). A `LightPost` carries post_id, author_id, created_at, in_reply_to_{post,user}_id, is_retweet (= `share.is_some()`), is_reply (= `reply.is_some()`), source_post/user_id, conversation_id, has_video (:226-244).
- `has_video` = exactly one media entity, it is a `VideoInfo`, duration >= 5,000 ms (:55-74).
- Retention `--post_retention_seconds` default 172800 (48h) (`thunder/args.rs:62-63`); inserts outside `[now-retention, now)` dropped (`thunder/posts/post_store.rs:132-135`); auto-trim by age and by per-author list size `MAX_POSTING_LIST_SIZE 5000` (`thunder/config.rs:12`, `post_store.rs:552-560`).
- Three per-author posting lists (`post_store.rs:89-92`): `original_posts_by_user` (not reply, not retweet, :161,178-186), `secondary_posts_by_user` (replies + retweets, :187-196), `video_posts_by_user` (has_video, or a retweet whose source is a non-reply video; replies never video-eligible, :198-220).
- Serving (`thunder/thunder_service.rs`): max results 1200 posts / 600 videos (`config.rs:1-2`), per-author caps `MAX_ORIGINAL_POSTS_PER_AUTHOR 50`, `MAX_REPLY_POSTS_PER_AUTHOR 30` (`config.rs:5-6`, clamped at `thunder_service.rs:234-245`), following list capped at 10,000 (`config.rs:3`, :247-256). Blacklisted authors never served: @grok 1720665183188922368, @gork 1909390269533011968, @products 1999031187604717568 (:33-38, :279). Ranking = newest-first truncation `score_recent` (:338-342). Scan at most 500 newest tiny posts per author (`config.rs:8`, `post_store.rs:324-328`).
- Secondary-list eligibility (`post_store.rs:337-365`): retweets of the viewer's own posts dropped (:338); a reply is returned only if its parent is an original post, OR the parent is itself a reply to the conversation root AND the reply is directed at a followed user (:345-363); parent not in store => dropped.
- home-mixer `ThunderSource` (`home-mixer/sources/thunder_source.rs:23-41`): enabled unless cached posts; `ThunderMaxResults 1200` (`params/param.rs:23-28`); passes `seen_ids` as exclusions; `per_author_limits: None` (defaults 50/30); replies registered in `query.in_network_replies`; ancestors = [parent, conversation root] (:89-95); served type ForYouInNetwork.
=> A follower can see the post on the very next For You request (subject to filters/ranking). No engagement needed.

### 1b. t = minutes — PopularPostsSource (OON, non-personalized)
- Enabled when `!in_network_only && EnablePopularPostsSource` (default true) (`home-mixer/sources/popular_posts_source.rs:147-151`); returns top `PopularPostsMaxResults 500` (`param.rs:1125-1130`) minus seen ids; served type ForYouPopularPosts.
- List built by `home-mixer/popular_posts_job.rs`: author set = top `TOP_POSTING_AUTHORS_FRACTION 0.00005` (0.005%) of 7-day active posters ranked by follower count (`home-mixer/util/popular_authors.rs:11,25-43`; snapshot from BigQuery, `popular_authors_job.rs`). Posts fetched from Thunder with `max_posts_per_author 50`, `max_replies_reposts_per_author 0`, originals only (`popular_posts_job.rs:298-300,343-345,359-362,380`). Only posts <= 24h old (`window_hours 24`, `util/popular_posts.rs:43,65`).
- Score = `views * (1-e^{-λ*24h}) / (1-e^{-λ*max(age,0.5h)})`, λ = ln2/8h, i.e. projected 24h views with an 8h half-life and a 0.5h floor (`util/popular_posts.rs:36-53`). Per author 5, total budget 500 (:39-40,77-85). Cache refresh every 60s (:7). views = `view_count` from engagement counts (`popular_posts_job.rs:404`).
=> Only mega-accounts' original posts; a fresh post qualifies as soon as its view velocity ranks in the global top 500.

### 1c. t = 2 min+ — Phoenix retrieval index (phoenix-rankall + strato)
Event layer (`phoenix-rankall-strato/`):
- PostCreation: forwarder on `content_understanding_realtime_unified_posts_v3`, `delay = 2.minutes` (`stream_forwarders/postCreationEventForwarder.strato:5-19`) -> `postCreationEventProcessor.strato` -> candidate processor with `eventSource = PostCreation`.
- Fav: forwarder on `timeline_events_prototype`, `delay = 2.minutes` (`favoriteEventForwarder.strato:5-17`) -> `favoriteEventProcessor.strato`. Rate limit per tweet via memcache (`tweetUpdateThresholdsCache.strato`, TTL 50h): first fav event always triggers if tweet < 49h old and favs < 2^30 (`lib/eventProcessing.strato:62-70`); later events trigger only when favCount >= next power-of-two threshold (`favoriteEventProcessor.strato:14-21`), >= 1 min since last update, <= 48h since first update, tweet age < 49h (`eventProcessing.strato:28-36,42-60`).
Candidate processor gates (`columns/phoenix_rank_all/phoenixRankAllCandidateProcessor.strato:419-539`), after hydrating lightweight tweet (user, text, created, reply, share, media, communities), UnifiedPostAnnotations, UEC engagement counts, author follower count:
- community post -> skipped (:470,481)
- reply (:483-495): only on Fav events; self-reply skipped; VF-drop or NSFW skipped; else `1fav_reply` (+`inReplyToPostId`) and, if favs >= 32, `32fav_reply` + metadata dump
- repost -> never indexed (:496-497)
- `shouldDropPost = VF shouldDropTweet(safetyLevel=TimelineHomeRecommendations) || isNsfwPost(annotations)` (:478-480; VF at `eventProcessing.strato:260-279`): dropped, except NSFW immersive video on Fav -> `nsfw_video` (:498-505)
- Fav, clean original (:508-519): `1fav` (+backup topic), `1fav_topic*` variants, `32fav` if favs >= 32, and if immersive video: `video`, `1fav_video`, `imagine` (grok-generated media); metadata + multimodal-embedding dumps
- PostCreation, clean original (:520-525): `post_creation`, `video` if immersive video, metadata dump
- `search_unfiltered` on Fav if favs >= 1 and not community/repost (:473-475)
- Video eligibility = media category TweetVideo/AmplifyVideo and every media entity a video with durationMillis > 10,000 (`eventProcessing.strato:23-24,403-418`); `isImaginePost` = media has grokPostId (:385-391).
- Metadata record per post: has_video, has_image, video_duration_ms, author_followers_count, engagement {retweet, reply, fav, quote, bookmark, view, not_interested, report, block} (:356-384; `phoenix-rankall/src/processor/record.rs:240-282`).
Index windows (`phoenix-rankall/src/config/mod.rs:169-225`; retention enforced by snowflake cutoff `store/base.rs:188-197`): Main: `post_creation` 24h; `1fav` 24h & 48h; `1fav_video` 48h, 2-4d, 4-14d, 4-30d; `32fav` 24h; `1fav_reply` 24h; `32fav_reply` 24h; `video` 48/96/168/336/720h; `nsfw_video` 48/168h; `evergreen_*` 5y. Topic: `1fav_topic*` 24h. Metadata: 24/48/72h. SID-tail: `tail` 24h = metadata records with author followers < `TAIL_MAX_AUTHOR_FOLLOWERS 1000`, `TAIL_MIN_FAV_COUNT 0` (`config/mod.rs:104-108`, `processor/sid_tail_processor.rs:61-83`). Static blacklist of post/author ids (`processor/blacklist.rs`).
Retrieval corpora served (`phoenix/crates/serving/xai-recsys-proto/proto/recsys.proto:394-414`; `phoenix/xrex/data/retrieval_dataset.py:290-325`): HOME(1)=`1fav_1day`; HOME_COLD(13)/HOME_HOT(14) = same file split by `cold_pool_mask` (fav < 8 AND views < 500 from `metadata_1day`, `phoenix/xrex/data/cold_pool_filter.py:16,26-34`) AND age <= `cold_start_max_age_seconds` 7200 (`cold_pool_filter.py:16`, prod config `phoenix/xrex/configs/xrecsys_two_tower.py:312`; split at `retrieval_dataset.py:535-567`); TAIL(10)=`tail_1day`; IMMERSIVE*=`video_2day/4day`, EVERGREEN=`video_4to14day`, IMAGINE=`imagine_4day`, ZERO_FAV(16) (served type ForYouPhoenixRetrievalZeroFav, `home-mixer/sources/phoenix_source.rs:165-170`; its corpus file is not in the python enum — the `post_creation` 24h index is the only zero-engagement index built, inference). At serving HOME_COLD rows are further age-trimmed but at least `large_k` newest are kept (`phoenix/xrex/inference/model_runner.py:4615-4668`).
home-mixer request (`sources/phoenix_source.rs:103-146`): enabled when `EnablePhoenixSource` and not in-network-only/cached; needs `retrieval_sequence`; asks `PhoenixMaxResults 1000` and `PhoenixColdStartMaxResults 200` (`param.rs:4-21`); new-user cluster switch when history length < `PhoenixRetrievalNewUserHistoryThreshold` (default 0 = off, :36-50); seen-post exclusions only if `PhoenixRetrievalExcludeSeenPosts` (default false). Companion sources: PhoenixTopicsSource (topic requests), PhoenixMOESource (`EnablePhoenixMOESource` false, max 0), SidSource (`EnableSidSource` false; 800 results, 50 seeds, 100/seed, prefix depth 3, `param.rs:759-788`), TweetMixer (`EnableTweetMixerSource` false).
=> A clean original post enters `post_creation` ~2 min after creation and `1fav`/HOME_COLD ~2 min after its first like; it is served from the cold slice (own 200-slot budget) for its first 2h while favs < 8 and views < 500, then competes in HOME_HOT. After 24h it leaves `1fav_1day`/HOME; after 48h AgeFilter drops it everywhere.

### 1d. t = first like — SimClusters
See §5. A post gets cluster membership on its first qualifying like (streaming), is a *candidate* when cosine > 0.5 to a seed and <= 48h old; it needs >= 8 likes before it can act as a *seed* embedding.

### 1e. What a post needs to reach OUT-OF-NETWORK viewers (summary)
| Path | Engagement | Author size | Type | Media | Language | Age |
|---|---|---|---|---|---|---|
| Popular posts | top-500 projected 24h views (8h half-life) | top 0.005% of 7d-active posters by followers | original only | none | none | <= 24h |
| Phoenix HOME (1fav) | >= 1 like | none | original (not reply/repost/community) | none; video indices need >10s video | none | <= 24h (48h window exists) |
| Phoenix HOME_COLD | < 8 likes & < 500 views (and >= 1 like to be in 1fav) | none | original | none | none | <= 2h |
| Phoenix TAIL (SidSource, off by default) | none | < 1000 followers | original | none | none | <= 24h |
| Phoenix 32fav / 32fav_reply | >= 32 likes | none | original / reply | none | none | <= 24h |
| SimClusters | >= 1 like from a user with InterestedIn; cluster score >= 0.001; cosine > 0.5 | none | any, but OON replies/retweets filtered later | none | none | <= 48h |
All OON paths then pass: not VF-dropped at TimelineHomeRecommendations (index-side and again `VFFilter`), author not NSFW (index-side `isAuthorEligible`/annotations; SimClusters `OONNsfwSimclustersFilter`), not a reply/retweet when OON (`OONRetweetReplyFilter`), <= 48h (`AgeFilter`). No language gate exists upstream of ranking (language is only a feature).

## 3. Filters and thresholds (pre-scoring, in order; `home-mixer/filters/`)
1. DropDuplicatesFilter — same tweet_id from several sources merged (retrieval_sources appended).
2. ZeroFavCodivertFilter — only when viewer in `ViewerZeroFavCodivertIsTreatment` (false): drops candidates retrieved *only* by ZeroFav dataset unless author in treatment (`zero_fav_codivert_filter.rs:52-99`).
3. CoreDataHydrationFilter — author_id == 0 dropped.
4. NewUserSoftNsfwFilter — `EnableNewUserSoftNsfwFilter` (false); account age < 604,800s (7d) and scoring seq < 100: drops OON posts labeled SOFT_NSFW (`new_user_soft_nsfw_filter.rs`, `param.rs:881-897`).
5. AgeFilter — snowflake age <= 48h (`MAX_POST_AGE 48*3600`, `params/config.rs:39`; `age_filter.rs:13-17`; unknown age → dropped).
6. SelfTweetFilter — author == viewer.
7. OONRetweetReplyFilter (`oon_retweet_reply_filter.rs:8-27`) — if in_network == false: drop retweets; drop replies unless `EnablePhoenixOonReplies` (false) and Phoenix-home retrieved (and root-reply if `PhoenixOonRepliesRootOnly`); also drop any reply with empty ancestors.
8. OONNsfwSimclustersFilter — SimClusters-sourced, OON, nsfw_author → drop.
9. RetweetDeduplicationFilter — dedup by retweeted_tweet_id|tweet_id.
10. IneligibleSubscriptionFilter — subscription_author_id not in viewer's subscriptions → drop.
11. PreviouslySeenPostsFilter — tweet_id, retweeted_tweet_id or in_reply_to_tweet_id in seen_ids or impression bloom filters (`util/candidates_util.rs:13-17`).
12. PreviouslySeenPostsBackupFilter — same against impressed_post_ids.
13. PreviouslyServedPostsFilter — same against served_ids (last 10 min / 100 posts, `param.rs:1154-1165`); enabled for all requests (`EnableServedFilterAllRequests` true).
14. ViewerMutedKeywordFilter — tokenized muted keywords vs tweet_text.
15. AuthorSocialgraphFilter — viewer mutes/blocks author, author blocks viewer, quoted author blocks viewer, viewer blocks quoted or retweeted user (`author_socialgraph_filter.rs:20-41`).
16. VideoFilter — only when `exclude_videos`: drops min_video_duration_ms or quoted_max_video_duration_ms present.
17. TopicIdsFilter — topic / excluded-topic requests only.
18. NewUserMinEngagementFilter (`new_user_min_engagement_filter.rs`, `param.rs:851-903`) — `EnableNewUserMinEngagementFilter` false; when account age < 1800s or resurrected < 1800s ago: OON posts need metric (fav | fav+reply+repost+quote | views, optionally ratio to views) >= `NewUserMinEngagementThreshold` (0.0).
19. InventoryHoldoutFilter — `EnableInventoryHoldout` false; deterministic hash(post,viewer)%100 < pct per kind (originals/replies/retweets all 0).
20. FavHoldoutFilter — `EnableFavHoldout` false; holdout % by fav_count: >1:2, >2:3, >3:3, >5:4, >7:4, >10:5, >15:5, >20:5, >30:6, >50:6, >75:7, >100:7, >150:8, >200:9, >300:10, >500:11, >750:12, >1000:13, >1500:13, >2000:14, >3000..>10000:15 (`fav_holdout_filter.rs:8-44`).
21. FairShareRankingFilter — proportional per-served-type cap to `PhoenixScoresResultSize 2800`.
Post-selection: VFFilter (Drop/Tombstone/NotEvaluated dropped; Allow/Interstitial/Avoid/Downrank kept, `vf_filter.rs:18-23`), AncillaryVFFilter (drop_ancillary_posts), AncestorVideoFilter (exclude_videos), DedupConversationFilter (one per conversation = min ancestor id, keep highest score), VideoCarouselFilter.
Other numeric gates: Thunder video >= 5s; rankall video > 10s; `MinVideoDurationMs 10_000` (VQV); SimClusters cosine > 0.5, age <= 48h, seed age <= 90d; cold pool fav < 8, views < 500, age <= 7200s; popular authors 0.005%, per-author 5, budget 500, window 24h; tail followers < 1000; rankall 32fav thresholds; fav-event retrigger at powers of two, min 1 min apart, 48h/49h windows.

## 4. Two-tower retrieval (`phoenix/xrex/models/recsys_two_tower_model.py`)
- Candidate (post) tower inputs (`_candidate_feature_tensors` :1853-1878, `_stack_candidate_tokens` :1880-1892): post-id hash embeddings (2 hashes, `HashKeys.item_hash_scales`, `recsys_embedding.py:184`, vocab 100M `xrecsys_two_tower.py:510-512`), author-id hash embeddings (2 hashes, `recsys_embedding.py:189`, vocab 30M), and a post semantic-ID token (6 levels × 256 codebook, prefix embeddings, `_build_post_sid_token` :1817-1840). Production config: `use_post_embedding False`, `use_post_sid True` (`xrecsys_two_tower.py:331-332`) — i.e. the home candidate tower sees only author identity + SID (content), no engagement counts, no text, no follower count, no language. Candidate tower = project-then-sum / concat-MLP, L2-normalized (:180-331). Safety-label mask bit AUTHOR_NSFW filters candidates at serving (`candidate_padding_mask` :621-645).
- User tower: action history (post/author hashes, action multi-hot, product surface, SIDs), optional user features/IP (:1621-1800).
- Labels (`RecsysTwoTowerModelConfig` :2896-2960): positive = SERVER_TWEET_FAV; hard negatives = CLIENT_TWEET_REPORT, NOT_INTERESTED_IN, SEE_FEWER, UNFOLLOW_AUTHOR, BLOCK_AUTHOR, MUTE_AUTHOR, NOT_RELEVANT; soft negative = CLIENT_TWEET_RECAP_NOT_DWELLED. Immersive head positives add reply/quote/retweet/video-quality-view/follow/bookmark/share. Loss = in-batch + global negatives softmax with logQ correction scale 2.0, fixed temperature 0.006, in-batch false-negative masking, positive-count user weighting ^0.5 (:2856-2868; prod :322-327).
- Oct 13 2026 "read all the way through" change (README.md:38-40; commit e1a0375): added an `ld` (long-dwell) head whose positive is `CLIENT_TWEET_RECAP_DWELLED` (:2953-2955), blended into the user query with `w_ld 0.75` alongside `w_fav 1.0` (prod `xrecsys_two_tower.py:293-296`; `query_head_weights` :2985-2988). Head names in prod: `["home","immersive","ld"]`; `ld` cannot be head 0 and fills the second post-table slot (validation added in e1a0375).
- Serving: per-dataset top-k over contiguous dataset ranges (`forward` :2279-2600); `head_dataset_mapping {HOME,HOME_COLD,HOME_HOT:0, IMMERSIVE*:1}` (:297-304); `dataset_capacities` per target type; home-mixer asks k=1000 for HOME and 200 for cold (§1c). Retrieved results tagged ForYouPhoenixRetrieval / ForYouPhoenixRetrievalCold / ForYouPhoenixRetrievalZeroFav (`phoenix_source.rs:165-170`).
- Cold start: HOME_COLD slice (fav < 8, views < 500, age <= 2h) with its own quota, age-trimmed at serving but never below `large_k` rows (`model_runner.py:4615-4668`); TAIL (< 1000 followers) and `post_creation`/ZERO_FAV indices exist for no-engagement posts but their home-mixer sources are off/experimental. Downstream (selection stage, out of scope) there is also a viewer-side cold-start slot: `ColdStartImpressionThreshold 200`, slots 15-16, `ColdStartFollowerCap 50000`, `ColdStartMaxPostAgeSecs 7200`, Thompson sampling Beta(0.75, 49.25) (`param.rs:608-686`).
- "Popular posts" are NOT a two-tower product; they are the view-velocity list in §1b.
- Reply two-tower v2 (`recsys_reply_two_tower_v2_model.py`, reply ranking): candidate tower DOES use numeric features — log1p fav/reply/repost/quote/view/followers/negative-feedback, video seconds, has_media, age minutes, rates fav/view, reply/view, repost/view, fav/(age+2h), fav/followers, language, plus placement features reply_section, author_verified, fav_by_root_author, focal_author_reply, self_reply (:729-820; indices `xrex/data/recsys/reply_features.py:15-32`); labels from `engagement_to_ids("reply")` incl. IsNegativeFeedback = block/mute/report (`constants.py:447-455`).

## 5. SimClusters: cluster membership for a new post
- Clusters: KnownFor = 20M producers × 145K communities (`MODEL_20M_145K_2020`, `home-mixer/sources/simclusters_source.rs:29`) from follow-graph community detection (`simclusters/simclusters_v2/scalding/UpdateKnownFor.scala`, `update_known_for/*`); InterestedIn(user) = weekly batch from KnownFor + follow graph, 30-day lookback, socialProofThreshold 2, maxClustersPerUser 50 (`scalding/InterestedInFromKnownFor.scala:15-16,37-38`).
- Tweet embedding = streaming Summingbird/Storm `TweetJob` (`simclusters_v2/summingbird/storm/TweetJob.scala:59-132`): on each UUA `ServerTweetFav` where the liker is not the author and tweet age < 3 days (`Configs.OldestTweetFavEventTimeInMillis`, `summingbird/common/Configs.scala:69`), look up the liker's InterestedIn, keep clusters with favScore >= 0.3 (`Configs.scala:30`, `SimClustersInterestedInUtil.scala:45-47`), add the cluster-normalized log-fav score as an 8h-half-life decayed value (`Configs.scala:39`). Per-tweet top-K clusters kept if score >= 0.02, cap 400 (`Configs.scala:55,59`; `TweetJob.scala:140-147`); cluster -> top-K tweets index kept if score >= 0.001, cap 1600 per cluster (`Configs.scala:51,61`; `TweetJob.scala:184-210`), plus video variant (high-res media) and author-hydrated variant.
  => Membership appears within seconds-minutes of the FIRST like from a user who has InterestedIn clusters; it decays with 8h half-life and the tweet stops updating at 3 days.
- Persistent embeddings (`storm/PersistentTweetJob.scala:23,50-57,113-123`): written only when favoriteCount >= 8, snapshotted at 2^3..2^24 likes; the "longest L2 norm" variant is the SEED embedding type used by home-mixer (`LOG_FAV_LONGEST_L2_EMBEDDING_TWEET`, `simclusters_source.rs:27`). So a post needs >= 8 likes to be a seed, 1 like to be a candidate.
- ANN serving (`simclusters/simclustersann/candidate_source/ApproximateCosineSimilarity.scala`, `SimClustersANNCandidateSource.scala:63-96`): source embedding truncated to `maxScanClusters 50`, per cluster up to `maxTopTweetsPerCluster 800`, candidates must be in [minAge 0h, maxAge 48h] (`SimclustersMaxCandidateAgeHours 48`, `param.rs:753-757`), cosine > minScore AND favL2NormScore > cosine/√2 (`ApproximateCosineSimilarity.scala:109-129`); home-mixer additionally keeps cosine > `POST_ANN_MIN_SCORE 0.5` (`simclusters_source.rs:35,204-211`), 200 per seed from server, 10,000/num_seeds per seed, interleaved round-robin, `MAX_RESULTS 800`, 10-min pod cache + shared cache (:25-36,56-59). Seeds = viewer's explicit+implicit engagement signals, newest first, each <= 90 days old (:36,223-228,287-311). Enabled when `EnableSimclustersSource` (true), not in-network-only, and the viewer has any post signals (:215-220). Author id filled by CoreData hydrator; candidates with author_id 0 dropped (:269-272).

## 6. Reposts, quotes, replies — differential treatment
Reposts (retweets):
- Thunder: stored in the secondary list (cap 30/author vs 50 originals), served only when the caller allows secondary posts; retweets of the viewer's own post dropped (`post_store.rs:187-196,338`); a retweet of a non-reply video is video-eligible (:200-206). Popular-posts job requests 0 secondary posts (`popular_posts_job.rs:359-362`).
- Phoenix index: never indexed (`phoenixRankAllCandidateProcessor.strato:496-497`), so OON retrieval returns the original post, not the repost.
- home-mixer: `OONRetweetReplyFilter` drops OON retweets; `RetweetDeduplicationFilter` collapses to the source post; all feature hydrators key on `get_original_tweet_id()` (counts, media, language, SID, engagers), Gizmoduck fetches both author and retweeted user; `as_tweet_info` sends the ORIGINAL tweet/author as the candidate with retweeting ids as side fields, and omits follower count / is_following / NSFW mask for the retweeter (`candidate.rs:326-381`); seen/served filters match on retweeted_tweet_id too; `AuthorSocialgraphFilter` drops if viewer blocks the retweeted user. Ranked-following feed has `FollowingRetweetDeduplicationFilter` (native post wins over its retweet).
Quotes:
- Treated as originals everywhere upstream (isRepost checks `share` only; a quote enters `1fav`/`post_creation` like any original; Thunder stores it as original).
- home-mixer: `QuoteHydrator` adds quoted id/author/text/media/duration and whether the quoted author blocks the viewer; `AuthorSocialgraphFilter` drops when either direction of block exists with the quoted author; VF checks the quoted post and `AncillaryVFFilter` drops the quote if the quoted post was dropped; `VideoFilter` counts quoted video; ranker gets `is_quote`, quoted ids and `quoted_content_features`.
Replies:
- Thunder: secondary list; only replies to an original, or to a reply-of-root directed at a followed user, are returned (`post_store.rs:341-365`); never video-eligible (:208-210); ancestors [parent, root] attached (`thunder_source.rs:89-95`).
- Phoenix index: only on Fav events, into `1fav_reply` (24h) and `32fav_reply` (>= 32 likes); self-replies and VF/NSFW-dropped replies excluded; never in `1fav`/`video` (`...CandidateProcessor.strato:483-495`). Reply retrieval into For You is gated by `EnablePhoenixOonReplies` (false) + `PhoenixReplyAncestorsHydrator`.
- home-mixer: OON replies dropped by default; any reply with empty ancestors dropped (`oon_retweet_reply_filter.rs:24-25`); `DedupConversationFilter` keeps one branch per conversation (min ancestor id) at selection; `SelfReplyChainFilter` (ranked-following) keeps a reply only if the first non-self ancestor author is followed; seen/served filters also match `in_reply_to_tweet_id`; Inventory holdout has a separate reply percentage; `TweetTypeMetrics` flags REPLY/HAS_ANCESTORS.
- Reply ranking inside conversations uses the separate reply two-tower v2 with reply-specific features (§4).
