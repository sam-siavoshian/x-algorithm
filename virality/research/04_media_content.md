# 04 — How X's For You stack understands images, video, audio and text content

Repo: /home/user/x-algorithm. All paths below are relative to that root unless absolute.

## TL;DR

1. **The Phoenix home ranker does NOT consume a raw CLIP (or any) media-content embedding.** The feature-prep stage has a `multimodal_embedding_dim` input slot, but it is 0 (`"multimodal_embedding_type": None`) on every registered ranking config, and the README says so explicitly. What the ranker *does* get is (a) **Semantic IDs** – 6 levels × 256 codes, residual-quantized from the post's 1024-d multimodal embedding (Qwen3-VL-Embedding-8B "v5", produced by grox) – which is a lossy content code, and (b) coarse media/author flags (`has_media`, `min_video_duration_ms`, author-NSFW bit, language code). `ContentFeatures` (hasVideo/hasPhoto/mediaCount/maxVideoDurationMs/weightedTextLen/newlineCount/hasUrl) are built and sent but no Phoenix serving code reads them (only the reply model reads `has_media`); they feed the separate vm-ranker debias payload.
2. Video reach is shaped mainly by **media-specific prediction heads** (video_quality_view "VQV", video_open, photo_expand, post_video, home_video_continuation_secs) and by **duration gating**: VQV counts only if `min_video_duration_ms > 10_000` and the viewer has < 10k followers. Current default weights: photo_expand 0.05; video_open, vqv, quoted_vqv, post_video, video_continuation all **0.0** (so media heads are currently near-irrelevant in the public weight defaults, but the machinery is there).
3. **Media labeling** runs off-request-path: (i) legacy DeepBird media models behind media-model-proxy (xx-nsfw, violence/gore, hateful symbols, category classification + CLIP-based "category classification embeddings" 256-d, fingerprinting), (ii) CLIP-embedding MLP classifiers (adult-content, pnsfwmedia), (iii) **Grox** – Grok/Gemma VLM classifiers over text + rendered images + sampled video frames + subtitles/ASR. Labels that matter for For You: `NSFW_HIGH_PRECISION`, `NSFW_HIGH_RECALL`, `SOFT_NSFW`, `NSFW_CARD_IMAGE`, `GORE_AND_VIOLENCE_HIGH_PRECISION`, `SPAM_HIGH_RECALL`, `RISKY_HIGH_VIZ_REPLY`, plus author labels (`NsfwHighPrecision/HighRecall/NearPerfect/AvatarImage/BannerImage`, `nsfw_admin/nsfw_user`). On the OON For You level (`TIMELINE_HOME_RECOMMENDATIONS`) every NSFW/gore media label is a hard **DROP**; in-network (`TIMELINE_HOME`) they are a **blur/interstitial**.
4. **Audio**: yes – grox runs ffmpeg → 16 kHz mono WAV (≤600 s) → an OpenAI-compatible chat endpoint with `audio_url` ("Transcribe this audio."), caches transcripts in Strato, and appends `Transcript:` to the multimodal-embedding document (v5, v8.2, v8-search). Video subtitles from Strato are also aligned to sampled frames for the safety VLMs. No audio features reach the ranker directly.
5. **Text quality / language / links / hashtags**: ranker gets `language_code` (user + post), `weightedTextLen`, `newlineCount`, `hasUrl` (built but unused by ranker), author-NSFW bit; home-mixer has URL-verdict / malicious-URL / untrusted-URL drops; Grox emits `slop_score`, `isHighQuality`, topic taxonomy, tags, description, and spam sub-types including `SpamEngagementBaiting`, `SpamHashTagAbuse`, `SpamMentionAbuse`, `SpamScamLinks`.

## 1. Does the Phoenix ranker consume media content embeddings?

**Definitive: No raw media embedding; yes a quantized derivative (Semantic IDs); plus media-type flags.**

Evidence:

- `phoenix/xrex/models/recsys_feature_prep.py:246` – `multimodal_embedding_dim: int = 0` in `FeaturePrepConfig`; `:1082-1095` – only when `> 0` is `batch["candidate_seq"]["embedding"]` projected (`cand_multimodal_proj`) and added to the candidate token.
- `phoenix/xrex/configs/xrecsys.py:76-85` – `multimodal_dim = EMBEDDING_CONFIG[multimodal_type][1] if multimodal_type is not None else 0`; `:342` and `:614` – `"multimodal_embedding_type": None` in `_home_direct_packed_base()` and `home_direct_packed_nano`. The production config `home_direct_packed` (`:532`) inherits None.
- `phoenix/xrex/data/recsys/recsys_batch.py:138-146` – `EMBEDDING_CONFIG = {"v1": ("embeddingV1Seq",1536), "v3":1024, "v5":1024, "v6":1024, "v8":1024}` – the training pipeline can carry grox v5/v8 embeddings but the ranker config turns the input off.
- `phoenix/README.md:411-426` – table row "Multimodal post embedding | off (`home_direct_packed` and `xrecsys_seqpack`) | — | — | —" and prose: "the multimodal-embedding input is off in both, and on every registered ranking config".
- **Semantic IDs ARE on**: `xrecsys.py:343` `"use_post_sid": True`; `phoenix/README.md:241-249` "posts additionally carry semantic IDs: residual-quantized codes over the post's multimodal embedding"; `phoenix/reference/README.md:110-117, 124-131` – production MM embedding = "render the post into one string with position-aware image-pad tokens, ChatML-wrap with the v5 system prompt, encode with the stock public `Qwen/Qwen3-VL-Embedding-8B`, truncate 4096 → 1024, L2-normalize"; SIDs = 6-level RQ (RQ-KMeans/RQ-VAE) codes over that vector. `recsys_sid.py:32-60` – learned prefix-2/prefix-3 tables (256² entries) → the ranker sees coarse topical/visual clusters, not the vector.
- Serving path: home-mixer hydrates SIDs (`home-mixer/candidate_hydrators/semantic_id_hydrator.rs:25-116`) and sends them in `TweetInfo.semantic_ids` (`home-mixer/models/candidate.rs` `as_tweet_info`, field `semantic_ids`), which the engine stamps into history and candidate tensors (`phoenix/crates/common/xai-recsys/src/util.rs:706, 1095-1100`).
- **Flags sent to Phoenix** (`home-mixer/models/candidate.rs` `as_tweet_info`): `min_video_duration_ms`, `tweet_bool_features.has_media`, `language_code`, `safety_label_mask` (= `SAFETY_BIT_AUTHOR_NSFW` when `nsfw_author_phoenix`), `content_features` / `quoted_content_features` (from `home-mixer/models/content_features.rs:8-36`: has_video, max_video_duration_ms, has_photo, media_count, weighted_text_len, newline_count, has_url). Phoenix model feature enums (`phoenix/xrex/data/recsys/feature_config.py:8-72`) contain **no** media columns at all – only engagement-count buckets, post age, `authorIsNsfwSeq`, language, surface, time. `grep` over `phoenix/crates` shows `content_features`/`has_media` are read only by the reply two-tower (`phoenix/crates/common/xai-recsys/src/reply.rs:473-479`, `firstVideoDurationMsSeq`). So for the home ranker, media-type flags are *transport* fields; the model's own content signal is SID + author hash + post-id hash + history.
- Where the raw 1024-d MM embedding IS used in retrieval: `phoenix/crates/serving/xai-recsys-engine/src/multimodal_retrieval.rs:133-166` – `prefetch_seed_embeddings` samples the viewer's recent positively-engaged post ids (age-limited) and fetches their MM embeddings from the mm-embedding server as query seeds (config `PrefetchMmQueryConfig`, `python.rs:3360-3380`). And in home-mixer's video carousel: `candidate_hydrators/video_embedding_hydrator.rs` fetches `tweet_multimodal_embeddings` (Manhattan, 1024-d, `clients/post_v8_search_embedding_client.rs:11-14`) for cosine dedupe at threshold **0.72** (`params/param.rs:1254-1257`) and SID-prefix dedupe at 3 levels (`:1242-1245`).

## 2. Media-specific prediction heads and how duration / media count enter

Action taxonomy (`phoenix/crates/serving/xai-recsys-proto/proto/recsys.proto`):
- `CLIENT_TWEET_VIDEO_QUALITY_VIEW = 13`, `CLIENT_TWEET_PHOTO_EXPAND = 14`, `SERVER_TWEET_POST_VIDEO = 44`, `CLIENT_TWEET_VIDEO_OPEN = 47`, `CLIENT_QUOTED_TWEET_VIDEO_QUALITY_VIEW = 48`, `CLIENT_QUOTED_TWEET_PHOTO_EXPAND = 49`, plus playback milestones 74-99 (`VIDEO_PLAYBACK_25/50/75/95`, `VIDEO_6SEC_VIEW`, `VIDEO_WATCH_TIME`, `VIDEO_MRC_VIEW`…) and `CLIENT_TWEET_VIDEO_SESSION = 111` (lines 470-568).
- Continuous heads: `ContinuousActionName { HOME_PROFILE_VISIT_SECS=0, DWELL_TIME=1, CLICK_DWELL_TIME=2, HOME_VIDEO_CONTINUATION_SECS=3, … ADS_VIDEO_WATCH_TIME_SECS=6, ADS_VIDEO_LENGTH_SECS=7 }` (lines 700-708).

Training: `phoenix/xrex/configs/xrecsys.py:271-302` – `home_video_continuation_loss_weight = 0.013` in `home_direct_packed` (`:552`), a CREAD regression on `HOME_VIDEO_CONTINUATION_SECS` conditioned on `CLIENT_TWEET_VIDEO_OPEN`, norm_scale 300 s, huber delta 5 s. The history stream also feeds `hist_home_video_continuation_vec` = log1p(clip(secs,0,300))/log1p(300) × learned vector (`recsys_feature_prep.py:1005-1027`).

Scoring (`xai-value-model/scoring.rs:85-215`, mirrored by `home-mixer/scorers/value_model.rs` and `vm-ranker/scoring/value_model.rs`):
- `vqv` term = `vqv_score × vqv_weight` only if `candidate.vqv_eligible`; `home-mixer/util/candidates_util.rs:19-34` – eligible iff viewer follower_count < 10 000 **and** `min_video_duration_ms > MinVideoDurationMs` (default **10 000 ms**, `params/param.rs:708-712`). Quoted VQV analog with optional duration check (`EnableQuotedVqvDurationCheck=false`).
- `video_continuation` = `video_open_score × home_video_continuation_secs × VideoContinuationWeight`; `user_video_continuation` = `video_open_score × viewer's average continuation secs` (`set_user_video_continuation`, `scoring.rs:220-236`).
- `photo_expand`, `video_open`, `post_video` are linear terms.
- Page-RL variant: `phoenix/xrex/models/page_rl.py:345-347` – `vqv_w = where(video_duration_ms > min_video_duration_ms(10 000), vqv, 0)`.
- Defaults (`home-mixer/params/param.rs:424-490`): `PhotoExpandWeight 0.05`, `VideoOpenWeight 0.0`, `VqvWeight 0.0`, `QuotedVqvWeight 0.0`, `PostVideoWeight 0.0`; `vm-ranker/params.rs:67-77` `VideoContinuationWeight 0.0`, `UserVideoContinuationWeight 0.0`. Video-carousel has its own weights (`VideoCarouselVideoOpenWeight`, `…ImmersiveVqvWeight`, `…VideoContinuationWeight`, `param.rs:1302-1330`).
- Duration / media count hydration: `home-mixer/candidate_hydrators/media_info_hydrator.rs:12-78` (has_media, has_photo, has_video, media_count, min/max_video_duration_ms from MediaInfoCache); `quote_hydrator.rs:112-182` (quoted media_count / max_video_duration_ms); `video_media_hydrator.rs:52-125` (video aspect_ratio, media_id, md5 hashes, carousel only); `tweet_type_metrics_hydrator.rs:80-84` buckets by duration. `phoenix-rankall/src/hydrate/post_metadata.rs:44-45` / `tweet_fields.rs:51-55` carry `hasImage/hasVideo/hasMedia/nsfwUser/nsfwAdmin` and `video_duration_ms` (`processor/metadata_processor.rs:77`) for the rank-all pipeline.
- Filters: `home-mixer/filters/video_filter.rs` (drop any post with a video when `query.exclude_videos`), `ancestor_video_filter.rs`, `oon_nsfw_simclusters_filter.rs` (drop OON SimClusters posts from `nsfw_author`), `new_user_soft_nsfw_filter.rs` (drop OON `soft_nsfw` for new accounts).

- Images resized to tile **448 px** (deluxe **600 px**), optional CLAHE / light-dark variants; a rendered **screenshot** of the post is added when ≥2 images and no video (`media_loader.py:95-125`).

- **Motion-reveal** frames (dense sampling, subtract static layer) for the "special video" / steganographic-porn flow (`convo.py:25-36`, `task_safety_ptos_special_video_filter.rs`).
- Leading-frames flow: videos ≥ 30 s cropped to first 10 s for adult re-screen (`ptos/constants.py:31-33`).
- Deluxe/second-pass tiers trigger at fav 64 / 128 / 512 / 1024 (`ptos/constants.py:25,33,40,43`).

### 3b. Label application and thresholds

- Legacy NSFW media model → botmaker derived features (`botmaker-rules/scarecrow/derived-feature/`): `IsHighPrecisionNsfwNewModelLogic` = `precisionNewNsfw ≥ 0.95`; `IsNearPerfectNsfwNewModelLogic` = `precisionNewNsfw ≥ 0.999`; `IsHighRecallNsfwNewModelLogic` = `recallNewNsfw ≤ 0.8568428` (image/gif) or `≤ 0.6` (**TWEET_VIDEO**) – i.e. recall-at-score operating point, video uses a looser bar. `NsfwTweetMediaProcessor.bot` maps detection label "3" → `NSFW_HIGH_PRECISION` (+`NSFW_NEAR_PERFECT` if score > 0.99), "4" → `NSFW_HIGH_RECALL`, and escalates to **author** labels after > 2 such posts in a day (`ApplyNsfwUserLabel.df`, HLL count > 2; 7-day label, 3-day for high-PageRank, or a manual report instead for gray/gold-verified).
- Violence/gore model → `ViolenceAndGore_ImageModel_MTT.bot`: TWEET_IMAGE precision > **0.6**, TWEET_VIDEO raw_score ≥ **0.95**, avatar/banner raw ≥ 0.85 (report only) → `GORE_AND_VIOLENCE_HIGH_PRECISION` tweet label (skipped for high-PageRank / gray-verified → manual review).
- `NSFW_Card_Image_Media_To_URL_Verdict.bot`: CARD_IMAGE with `IsNearPerfectNsfw` → URL verdict `NSFW_CARD_IMAGE` (7 days) → `NSFW_CARD_IMAGE` tweet label.
- Grox PTOS → `grox/flows/ptos/task_write_safety_post_annotations_result_sink.py:190-260`: `ViolentMedia*` (any non-NoViolation) **and post has media** → `GoreAndViolenceHighPrecision`; `AdultContentSexualHard` → `NsfwHighRecall` (+ `NsfwHighPrecision` if media); `AdultContentSexualSoft` → `SoftNsfw`; Spam `EngagementBaiting/EngagementFarming/CardManipulation` (always) or other spam types (unless high-PageRank/grey-badge) → `SpamHighRecall`; `HateOrAbuseInsultsWithTarget` → `FosnrAbuseInsults`; self-harm encouragement → bounce; `ChildSafetySexualExploitation` → suspension. Also writes `SafetyBoolMetadata{isGore,isNsfw,isSoftNsfw,isSpam}` (`:78-147`). Cross-validation: child-safety/violent-media/illegal verdicts are re-judged by Grok 4.5 (`classifier.py:170-330`); adult verdicts are cross-checked by the `safemodel` sex-and-nudity classifier over up to 8 uniformly sampled stills per video / 12 payloads per post, positive buckets {"R","X"} (`task_safety_ptos_safemodel_sex_nudity.py:21-31`).
- Grox UPA → `UnifiedPostAnnotations` (`grox/flows/upa/task_write.py:164-190`) and `grokUpaActionWithLabels` (labels applied by Strato from `TweetBoolMetadata`). Grox spam score ≥ **0.97** on a reply → `RISKY_HIGH_VIZ_REPLY` for 14 days unless reply is from conversation author / high-PageRank (`GroxTweetProcessor.bot`).

### 3c. Visibility-filtering consequences (For You)

home-mixer evaluates in-network posts at `SafetyLevel::TimelineHome` and OON posts at `TimelineHomeRecommendations` (`home-mixer/candidate_hydrators/vf_candidate_hydrator.rs:92-106`).

`TIMELINE_HOME_RECOMMENDATIONS` (OON) (`visibility-filtering/rules/levels.rs:318-361`): after takedowns/age-gating → `HOME_BLURS` → **DROP** for `NSFW_USER_TWEET_FLAG`, `NSFW_ADMIN_TWEET_FLAG`, `GORE_AND_VIOLENCE_HIGH_PRECISION`, `NSFW_HIGH_RECALL`, `NSFW_HIGH_PRECISION`, `NSFW_CARD_IMAGE`, `SOFT_NSFW` (new accounts only, `tweet_rules.rs:912-922`), then `OON_POST_DROPS` = `DO_NOT_AMPLIFY`, `MALICIOUS_URL`, `SPAM_HIGH_RECALL`, (Brazil), then `FOSNR_ABUSE_INSULTS`. These are unconditional on label (`tweet_rules.rs:478-498`, audience NonAuthors).

`TIMELINE_HOME` (in-network) (`levels.rs:298-316`): no NSFW/gore drops; `HOME_BLURS` only = `NSFW_HIGH_PRECISION` → blur Nudity/Sensitive interstitial, `GORE_AND_VIOLENCE_HIGH_PRECISION` → blur Violence, `NSFW_CARD_IMAGE`, `NSFW_ADMIN`, `NSFW_USER` → blur Sensitive (when viewer does not allow sensitive media) (`levels.rs:133-140`, `tweet_rules.rs:456-475, 586-593`).

Sensitive viewers (logged out / underage / no stated age in NsfwGating countries): drop on `HAS_NSFW_MEDIA_LABEL` = {NSFW_HIGH_PRECISION, NSFW_HIGH_RECALL, GORE_AND_VIOLENCE_HIGH_PRECISION} when `TweetHasMedia`, or `IS_NSFW_FLAGGED` (author/tweet nsfw flags), or `NSFW_TEXT`/`NSFW_CARD_IMAGE` (`rule_spec/conditions.rs:6-31`, `tweet_rules.rs:294-379`). `IS_NSFW_SENSITIVE_TWEET` additionally includes `NSFW_TEXT_HIGH_PRECISION`, `NSFW_VIDEO` (`conditions.rs:48-57`).

Under-the-hood descriptions confirm effect ("hidden from recommendations to non-followers…", `under-the-hood/strato/lib/underTheHoodLabels.strato:4-33, 136-160`). Author-level NSFW labels (`NsfwHighRecall/HighPrecision/NearPerfect/AvatarImage/BannerImage`) likewise hide all of an account's posts from non-followers; home-mixer additionally hard-drops OON SimClusters posts from `nsfw_author` and passes `SAFETY_BIT_AUTHOR_NSFW` into the ranker (`feature_config.py:14, 42` `authorIsNsfwSeq`).

Phoenix also carries an `OutOfNetwork` "post_video" head and the `RETRIEVAL_DATASET_TYPE_IMMERSIVE_32FAV_VIDEO_14_TO_30_DAY` retrieval dataset (`recsys.proto:412`), and SimClusters has a dedicated `ClusterTopMediaTweetsJob` that indexes **video** posts per cluster (`isMediaTweet` = has `MediaType.Video`, `simclusters/.../ClusterTopMediaTweetsJob.scala`).

## 6. Recommendation: media representation for a virality predictor that mirrors X

What X's ranking actually "sees" of content is, in order of influence:
1. **A VLM-derived multimodal document embedding, quantized.** Build the same thing: render each post as one text document – author line, `Post text:` (t.co stripped), card title/description, article title, quoted post – with image placeholders for each image, **up to 4 uniformly sampled video frames per video** (first/last + jittered midpoints), and `Transcript: <ASR ≤2000 chars>` – and embed it with **Qwen3-VL-Embedding-8B** (open weights) using X's own instruction ("Represent this X post (formerly Twitter) for recommendation: capture its topic, intent, key entities, and likely engagement"), truncate to 1024 and L2-normalize. Then fit a 6×256 residual-quantizer (RQ-KMeans is fine) and feed **SID prefix codes (levels 1-3)** plus the raw 1024-d vector to your model. The SID prefixes mimic exactly the ranker's content token; the raw vector mimics MM retrieval seeds / carousel dedupe. Do not spend effort on TwitterCLIP ViT-B/32-256: it is used for safety classifiers, not for ranking, and it only ever sees frame 0 / thumbnail of a video.
2. **Media-type and duration scalars** the request path carries: `has_media`, `has_photo`, `has_video`, `media_count`, `min_video_duration_ms`, `max_video_duration_ms`, `video_aspect_ratio` (carousel), quoted-post equivalents, `is_gif`. Add the engineered gates: `video_duration > 10 s` (VQV eligibility), author follower count < 10k, and the v8.2 bitrate buckets (SD <1.5 Mbps, HD, Full HD ≥5 Mbps) and humanized duration – they are literally in the embedding text.
3. **Text scalars**: `weighted_text_len` (X weighting), `external_url_count`, `newline_count`, language, mention count, whether the only URLs are media attachments.
4. **Safety-label proxies as hard features (they are hard drops/blur for OON reach):** replicate (a) an adult/nudity score with video-specific thresholds (image: high-precision ≈ P≥0.95, near-perfect ≥0.999; video: looser recall bar), (b) a violence/gore score (image precision > 0.6 / video raw > 0.95), (c) a soft-NSFW / suggestive flag, (d) author-level NSFW propensity (≥3 flagged posts/day → account label hides *all* posts from non-followers), (e) engagement-bait / engagement-farming / card-manipulation / hashtag-abuse / scam-link spam classes, (f) a "slop" score and `isHighQuality` (Grox emits them; treat as experimental since nothing downstream reads them yet). Any post predicted positive on (a)-(e) should have OON reach set near zero in your model, and in-network reach down-weighted (blur).
5. **Video frame sampling rate to mimic**: for the embedding, 4 uniform frames (first, last, two jittered interior); for safety screens, 20 frames at 448 px (30 @ 600 px for popular posts) tiled into storyboards, plus up to 3 shot key frames from the first 3 s scanned at 15 fps and up to 3 "ranked" frames found by 3 fps coarse / 15 fps fine embedding-similarity search; audio at 16 kHz mono ≤ 10 min through an ASR LLM. If you only afford one setting, use ~1 frame/s capped at 20, plus first and last frame, 448 px, and keep the ASR transcript – that covers both the embedding and safety views.
6. **Targets to predict**: X's video heads are `video_quality_view` (gated by duration), `video_open`, `home_video_continuation_secs` (conditioned on video_open, CREAD, capped 300 s), `photo_expand`, `post_video`; the public default weights put almost all mass on fav/reply/repost/share/dwell, so for a virality predictor use media representations to predict those plus `video_quality_view` and continuation seconds as auxiliary heads, rather than modeling "video vs photo" as an intrinsic boost – there is none in the code; media only matters through the engagement it is predicted to earn and through safety suppression.
